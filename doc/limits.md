# 已知限制

这份文档列出当前版本做不到、或者会有条件失效的地方。额度估算本身的取整、延迟等固有限制见 [quota-estimation.md](quota-estimation.md)，实现原因见 [implementation.md](implementation.md)。

## 界面依赖

- 浮窗依赖 Codex Desktop 当前的 DOM 结构。官方更新界面后，定位可能失效，需要更新 `placement.mjs` 与 `widget-overlay.mjs` 里的选择器和几何规则。
- 界面结构与预期不符、或输入栏底部没有足够空间时，浮窗和所有标记会自动隐藏，不会遮挡原生按钮；此时 `window.__CODEX_USAGE_WIDGET_DEBUG__` 会给出 `status: "degraded"` 和原因。
- 逐轮标记必须同时找到对应的回复文字和操作按钮行才会出现，任一项缺失时该轮不显示标记。
- 侧栏标记与逐轮标记默认关闭，开启后也依赖同样的结构识别。

## 启动方式

- 没有在“已运行且未开启 CDP 端口”的 Codex 进程里强行开启调试端口。这种情况下启动器只会唤出窗口，需要从托盘完整退出后重新双击 EXE，才能注入浮窗。
- 启动器与浮窗要求 Windows：激活走 MSIX 应用模型，运行时目录、Hook 命令路径都基于 `%LOCALAPPDATA%`。
- CDP 与 Hook 端口只监听回环地址，不支持远程或局域网访问（这是有意的）。

## 数据完整性

- Hook 可能被跳过、投递失败或未获信任；这些情况下数据由转录补录兜底，更新会晚一个扫描周期（15 秒），且只有重新解析过的记录才参与额度估算。
- 历史记录中未归属到具体轮次的 Token 不会被补算：会话累计只统计已记录轮次，并在数值旁显示 ⓘ 提示。
- `state.json` 写入失败时内存状态会回滚，`GET /health` 报出写入错误；此时的估算基于上一次成功写入的数据。
