# 额度估算

浮窗上的剩余额度直接来自 Codex，是准确的；估算指的是“这一轮对话大概吃掉了多少额度”。这份文档说明它是怎么算出来的、什么时候会显示不出来，以及代码里对应哪些实现。

用法与安装见 [README](../README.md)，其余实现细节见 [implementation.md](implementation.md)。

## 参考成本

普通输入、缓存输入、缓存写入及输出按模型权重计算参考成本，权重参考 [OpenAI API 标准价格](https://developers.openai.com/api/docs/pricing)。它只用于相对估算，**不是 ChatGPT 的额度账单**。

## 用真实额度反推

本项目不用猜测的固定预算，而是拿**同一轮对话内部的额度快照**去反推：

- 以该轮相同区间的 Token 成本作分母，用额度增量作分子，得到该模型的换算系数；
- 按额度窗口、模型和重置周期分别分组，零增量区间也计入成本；
- 排除已知并发、额度重置、计数回退和时间异常的观测；
- 旧证据按 21 天半衰期衰减，同模型至少积累 2 个百分点的观测增量才给出估算。

账户快照仍可能取整、延迟或包含本机未记录的其它活动（比如同一账号的其它设备），因此估算值显示“约”。

## 显示规则

| 情况 | 显示 |
| --- | --- |
| 逐轮 Token 无法确认 | `--` |
| 有可靠 Token 数据，但模型未知或缺少同模型校准证据 | 无法估算 |
| 校准证据不足，但本轮有连续额度快照 | 至少 x%（快照间已观测到的最低消耗比例） |
| 连快照也不足 | 无法估算 |

Token 用量仍独立显示，已知价格的模型也继续显示参考费用。不再使用默认 API 费用预算换算额度，也不借用其它模型的系数；旧设置中的预算字段仅为兼容保留，不参与计算。

## 会话累计的含义

会话累计表示**整个会话历史相当于完整额度窗口的比例**，不代表当前 5 小时 / 每周窗口已用额度。若会话总 Token 大于已记录逐轮 Token 之和，但已记录轮次均可验证，则显示这些轮次的累计估算，并在数值后显示 ⓘ 小标记，悬停可见“仅含已记录轮次，历史 token 未全部归属，实际累计可能更高”。未归属的历史 Token 不按固定缓存比例补算，完整会话的参考费用仍不提供。

## 实现细节

对应 `src/quota-estimator.mjs`：

- 权重表 `MODEL_WEIGHTS` 用 OpenAI API 短上下文标准价格（每 1M token）作为相对权重，按模型名前缀匹配；未知模型回落到 `gpt-6-sol` 并标记 `known: false`，浮窗据此显示“无法估算”而不是拿别人的系数硬套。
- `weightedCost` 先把 cached 与 cacheWrite 各自夹在 input 之内，避免异常数据重复计数，再按 `(uncached·input + cached·cached + cacheWrite·cacheWrite + output·output) / 1e6` 求和。
- `quotaCalibration` 只用同一轮内的 `codex` 账户快照，按窗口 × 模型 × 重置周期分桶；用 30 分钟上限过滤异常区间，按 21 天半衰期衰减旧证据，丢弃并发/重置/回退观测；零增量区间同样计入成本；系数 = Σ增量 / Σ成本，同模型至少 2 个百分点的观测增量才产出 `calibrated`。
- 校准证据不足但本轮有连续快照时退回 `observed-lower-bound`：取快照间已观测到的最低消耗比例，展示为“至少 x%”。
- 旧的 `budgets` 设置字段只为兼容保留，不参与任何计算。

改动这里的判定逻辑时，`test/quota-estimator.test.mjs` 覆盖了分桶、衰减、回退与显示分支，先跑 `npm test`。
